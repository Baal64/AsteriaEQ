# ADR-0008 - Hardware STEP Pulse Generation

- **Status:** Accepted
- **Date:** 2026-08-05
- **Decider:** Alexandre Ba

---

## Context

Asteria EQ controls two independent stepper motors:

- Right Ascension (RA)
- Declination (DEC)

Both motors are driven by TMC2209 stepper drivers through STEP and DIR signals.

The firmware architecture already separates:

- motion planning (`MotionSource`);
- motion arbitration (`AxisController`);
- axis state (`Axis`);
- motor driver (`StepDirMotorDriver`);
- pulse generation (`IStepPulseGenerator`).

The remaining design decision concerns the implementation of the STEP pulse generation.

Two solutions were evaluated.

---

## Decision

STEP pulses are generated by the hardware timers of the ATmega32U4.

Each axis uses an independent hardware timer connected to its compare output.

The firmware never toggles the STEP pin directly.

Instead, it computes the requested pulse frequency and configures the corresponding hardware timer.

The timer autonomously generates the STEP signal.

Initial allocation:

| Axis | Timer | Compare Output |
|------|-------|----------------|
| RA | Timer1 | OC1A |
| DEC | Timer3 | OC3A |

---

## Consequences

### Positive

- Deterministic pulse generation.
- Virtually zero timing jitter.
- Minimal CPU usage.
- Independent pulse generation for both axes.
- Excellent scalability.
- Clear separation between motion planning and hardware timing.
- Tracking accuracy is not affected by firmware workload.

### Negative

- STEP outputs are constrained to timer compare pins.
- Timer1 and Timer3 become reserved resources.
- The implementation is hardware-specific and belongs to the platform layer.

---

## Alternatives Considered

### Option 1 – Timer Interrupts

Generate STEP pulses inside a Timer ISR.

**Advantages**

- Any GPIO can be used.
- Pulse shape is fully programmable.

**Disadvantages**

- CPU interruption at every pulse.
- Timing jitter due to interrupt latency.
- Increased firmware complexity.
- Reduced scalability.

---

### Option 2 – Hardware Compare Outputs (Selected)

Generate STEP pulses directly using the timer compare outputs.

**Advantages**

- Hardware-generated pulses.
- No CPU intervention once configured.
- Excellent timing precision.
- Low software complexity.
- Independent operation of both axes.

This option was selected.

---

## Impact on Architecture

This decision preserves the current software architecture.

The `IStepPulseGenerator` interface remains unchanged.

Two implementations coexist:

- `SimulatedStepPulseGenerator`
- `Atmega32u4StepPulseGenerator`

The Core layer remains completely independent of the hardware platform.

Only the Platform layer accesses timer registers.

## Notes

This decision follows one of the fundamental architectural principles of Asteria EQ:

> **Software decides. Hardware executes.**

The firmware computes *what frequency* is required.

The hardware timers determine *when each pulse occurs*.
